# 大乐透/双色球合规 H5 选号服务设计

日期：2026-06-02

## 目标

建设一个面向中国大陆成年用户的 H5 网站，提供超级大乐透和双色球的号码生成、历史开奖数据分析、组合解释和原创正能量寄语。产品只销售号码生成与数据分析服务，不销售彩票，不代购彩票，不出票，不合买，不追号，不兑奖，不承诺中奖。

首版先做 H5，验证用户使用、留存和变现意愿；产品稳定后再规划微信小程序。

## 产品定位

产品定位为“大乐透/双色球智能选号助手”。用户每天可以免费生成 3 组号码；免费次数用完后，可以通过广告解锁或购买次数包/会员获得更多生成次数。所有付费权益均为数字内容服务，不涉及彩票交易。

核心原则：

- 合规优先：不提供任何互联网售彩、代购、出票或购彩跳转。
- 诚实表达：号码生成基于随机、均衡筛选和历史数据参考，不构成中奖预测。
- 低刺激设计：避免暴富、包中、稳赚、翻身、投资收益等诱导性表达。
- 理性使用：核心页面展示 18+、随机性、理性购彩和量力而行提示。

## 用户与场景

首版服务两类主要用户：

- 普通购彩者：想快速获得几组顺眼号码，操作越简单越好。
- 数据型用户：希望查看历史开奖、冷热号、遗漏值、奇偶比、区间分布等基础分析。

不把专业预测、社区晒单、中奖故事、合买组织作为首版目标。

## 信息架构

### 首页

首页承担快速进入选号的职责：

- 产品名和 18+ 理性使用提示。
- 超级大乐透、双色球入口。
- 今日剩余免费生成次数。
- 最近期开奖信息。
- 不售彩、不代购、不出票声明。

### 选号页

选号页是核心工具页：

- 彩种切换：大乐透、双色球。
- 生成模式：随机生成、均衡生成、数据参考。
- 号码结果展示：按彩种使用不同颜色区分前后区、红蓝球。
- 组合解释：奇偶比、大小比、区间分布、连号情况、历史数据参考说明。
- 原创正能量寄语。
- 剩余次数展示。
- 次数用完弹层：广告解锁、购买次数包、开通会员。
- 合规提示：仅供娱乐参考，不构成中奖预测。

首版不提供“复制去购买”“立即购彩”“下单”“出票”等动作。

### 数据分析页

数据分析页服务留存和搜索流量：

- 最新开奖记录。
- 历史开奖列表。
- 热号和冷号。
- 遗漏值。
- 奇偶分布。
- 大小分布。
- 区间分布。
- 奖池趋势。

页面声明：开奖数据来自公开渠道整理，实际结果以官方公告为准。

### 我的页面

我的页面管理用户权益和合规材料：

- 今日剩余免费次数。
- 广告解锁次数。
- 会员状态。
- 次数包余额。
- 生成历史。
- 订单记录。
- 服务协议。
- 隐私政策。
- 理性使用声明。
- 18+ 声明。

## 彩种规则

### 超级大乐透

- 前区：1-35 选 5 个号码。
- 后区：1-12 选 2 个号码。
- 每组号码必须合法、去重、排序展示。

### 双色球

- 红球：1-33 选 6 个号码。
- 蓝球：1-16 选 1 个号码。
- 每组号码必须合法、去重、排序展示。

## 选号策略

系统内部将算法命名为“选号策略”，不使用“预测模型”作为产品表达。

### 随机生成

按彩种规则完全随机生成合法号码。该策略最适合作为合规基线，也用于对照测试。

### 均衡生成

在合法随机号码上进行筛选，使组合满足基础分布条件，例如：

- 奇偶比不过度极端。
- 大小比不过度极端。
- 区间分布相对分散。
- 连号数量受限。
- 和值落在历史常见区间内。

均衡生成只表示组合结构更均衡，不表示中奖概率更高。

### 数据参考

根据历史开奖统计生成带权重的候选组合，参考维度包括：

- 近期热号。
- 长期冷号。
- 遗漏值。
- 最近若干期重复情况。
- 历史分布区间。

页面必须说明：历史数据只用于娱乐分析，彩票开奖具有随机性，历史分布不影响未来开奖结果。

## 结果解释

每组号码生成后保存以下信息：

- 彩种。
- 策略。
- 号码。
- 生成时间。
- 组合解释。
- 原创寄语。
- 合规提示版本。

组合解释以简短、可读、克制为原则。例如：

- “本组红球奇偶比为 3:3，分布较均衡。”
- “前区号码覆盖低中高三个区间，未出现过度集中。”
- “历史数据仅用于娱乐分析，不构成中奖预测。”

## 正能量寄语

每组号码附赠一句原创短句，用于增强仪式感和分享体验。

规则：

- 默认使用原创短句，不署现代名人姓名。
- 可以使用公版古诗词风格表达，但不虚构出处。
- 不把寄语写成中奖暗示。
- 不出现“必中奖”“转运暴富”“一夜翻身”等表达。

示例：

- “今天适合稳稳前进，把好运留给有准备的自己。”
- “认真生活的人，也值得被温柔地照亮一下。”
- “把期待放轻，把脚步走稳。”

## 权益与商业化

### 免费额度

每个用户每天免费生成 3 组号码。免费额度按自然日重置。

### 广告解锁

免费额度用完后，用户可通过观看广告解锁额外生成次数。首版先实现模拟广告解锁，后续接入真实激励广告 SDK。

### 付费权益

付费权益包括：

- 次数包：购买固定数量的号码生成次数。
- 会员：每日更多生成次数、高级数据分析、更多生成历史保存。

支付文案必须明确：

- 购买的是号码生成与数据分析服务。
- 平台不销售彩票。
- 平台不代购彩票。
- 平台不承诺中奖。

首版先实现模拟支付和订单模型，不接真实支付。

## 不可逾越风险门禁

以下约束优先级高于所有产品、增长、商业化和技术需求。任何需求、页面、接口、文案、运营活动、广告素材或第三方合作只要触发任一门禁，必须立即停止设计和开发，除非经过专项法律合规审查并形成新的书面结论。

### 互联网售彩红线

产品不得直接或间接形成彩票交易闭环。禁止能力包括：

- 代用户购买彩票。
- 收取彩票款。
- 向彩票店、销售终端或第三方售彩平台提交号码。
- 出票、验票、兑奖。
- 合买、跟单、追号、托管购买。
- 引导用户联系线下店代买。
- 提供购彩跳转、购彩金额计算、下单确认、出票状态等交易相关功能。

产品所有收费只能对应号码生成、历史数据分析、生成记录保存等数字内容服务，不得与彩票面值、彩票注数购买或中奖结果绑定。

### 预测和诱导红线

产品不得明示或暗示可以预测开奖结果，不得让用户理解为付费后号码更准。禁止表达包括：

- 专家预测、内部号、杀号、定胆、必中、包中、稳赚。
- 提高中奖率、提升命中率、翻身、暴富、上岸、投资回报。
- 购买高级服务可获得更高概率号码。
- 用户中奖案例、中奖故事、晒单排行榜、跟买战绩。
- 使用名人、机构或虚构专家为号码背书。

允许表达只能是随机生成、均衡筛选、历史数据参考、娱乐选号、理性使用。

### 平台审核红线

H5 是首发载体。微信小程序、App Store、安卓应用市场、公众号、短视频广告投放都必须单独做平台规则审查。

特别约束：

- 微信小程序不得在未完成专项合规评估前启动开发或提审。
- 真实广告 SDK 不得在隐私政策、用户授权和数据处理说明完成前接入。
- 真实支付不得在服务协议、退款规则、发票/订单规则和法律合规复核完成前上线。
- 任何渠道投放素材不得使用刺激购彩、中奖承诺、预测命中等表达。

### 资质和备案红线

大陆公开上线前必须完成网站备案和经营模式复核。若产品通过互联网有偿提供信息服务，是否需要经营性互联网信息服务相关许可必须在上线前由专业机构确认。

上线前必须具备：

- ICP 备案或与实际部署地区匹配的合规上线方案。
- 服务协议。
- 隐私政策。
- 未成年人限制说明。
- 数字内容服务说明。
- 退款和订单规则。
- 广告与支付接入前的专项合规记录。

### 隐私和广告红线

产品不得超范围收集个人信息。接入广告、支付、统计分析或风控 SDK 时，必须遵守最小必要原则。

上线前必须明确：

- 收集哪些信息。
- 为什么收集。
- 保存多久。
- 是否共享给第三方。
- 用户如何撤回授权和删除账号。

未完成隐私告知和用户同意流程前，不得接入真实广告 SDK、支付 SDK、设备指纹、精准营销或跨应用追踪。

### 竞品和差异化风险

市场上已有随机选号、开奖查询、走势分析和彩票数据类产品。首版不能仅复制“随机选号器”，否则差异化不足、付费转化弱、平台审核风险却不低。

首版差异化必须来自：

- 合规克制的产品表达。
- 大乐透和双色球的清晰数据解释。
- 每日 3 组免费额度与权益体系。
- 原创正能量寄语。
- 明确的不售彩、不预测、不诱导边界。

竞品存在不代表其模式一定合规，也不能作为本项目越过上述红线的依据。

## 数据来源与同步

开奖数据采用自动同步为主、手动导入兜底的策略。

### 初始数据

开发阶段由导入脚本导入超级大乐透和双色球历史开奖数据。用户不需要手动逐条录入数据。

初始字段包括：

- 彩种。
- 期号。
- 开奖日期。
- 开奖号码。
- 销售额。
- 奖池。
- 一等奖注数。
- 一等奖奖金。
- 数据来源。

部分公开数据缺失时，允许销售额、奖池、奖金等字段为空，但期号、日期、号码必须完整。

### 定时同步

上线后通过定时任务在开奖日后同步最新期开奖数据。

同步流程：

1. 拉取公开开奖数据。
2. 校验期号、日期和号码合法性。
3. 与已有数据去重。
4. 写入数据库。
5. 记录同步日志。
6. 异常时通知管理员。

### 手动兜底

后台保留 CSV 导入和修正能力，用于数据源异常或历史数据补齐。CSV 导入必须经过同样的数据校验。

## 数据模型

建议核心表：

- users：用户基础信息和年龄确认状态。
- lottery_types：彩种规则。
- lottery_draws：历史开奖数据。
- number_generations：用户生成记录。
- entitlements：用户可用次数和会员权益。
- entitlement_events：权益流水。
- orders：服务订单。
- ad_unlock_events：广告解锁记录。
- compliance_notices：合规提示版本。
- sync_jobs：开奖数据同步日志。

## 服务边界

### LotteryCatalog

管理彩种规则、号码范围、开奖频率和概率说明。

### DrawData

负责历史开奖数据、最新开奖、基础统计和数据校验。

### NumberGenerator

负责随机、均衡、数据参考三种选号策略，并输出组合解释。

### Entitlement

负责每日免费次数、广告解锁次数、会员权益和次数包扣减。

### PaymentAndAdUnlock

负责模拟支付、订单记录、广告解锁记录和后续真实支付/广告接口适配。

### Compliance

统一管理页面提示、敏感词、合规声明和付费服务说明。

## 技术建议

推荐技术栈：

- 前端：Next.js + React，先做移动优先的 H5 响应式页面。
- 后端：Next.js API 路由或独立服务。
- 数据库：PostgreSQL。
- 缓存：Redis，用于限流、免费次数和短期状态。
- 定时任务：同步开奖数据。
- 测试：单元测试、接口测试、浏览器端流程测试。

MVP 可以先简化为：

- Next.js 全栈应用。
- PostgreSQL 或 SQLite。
- 模拟广告。
- 模拟支付。
- 脚本导入初始开奖数据。

## 错误处理

号码生成失败：

- 不扣减用户次数。
- 展示“生成失败，请稍后重试”。
- 记录错误日志。

权益扣减失败：

- 不展示生成结果。
- 提示用户重试。
- 保证权益流水和生成记录一致。

开奖数据同步失败：

- 保留上一期可用数据。
- 在管理日志中标记失败原因。
- 前端不展示未校验的新数据。

CSV 导入失败：

- 返回具体错误行号和原因。
- 不写入部分失败数据。

支付或广告模拟失败：

- 不增加权益。
- 给出明确提示。
- 保留事件日志，便于排查。

## 验收标准

产品可用：

- 用户可以选择大乐透或双色球。
- 用户每天能免费生成 3 组号码。
- 免费次数用完后无法继续免费生成。
- 用户可以通过模拟广告或模拟付费获得额外次数。
- 每组号码符合对应彩种规则。
- 每组号码都有组合解释和原创寄语。
- 用户能查看历史开奖和基础统计。

合规可控：

- 不存在彩票销售、代购、出票、合买、追号、兑奖流程。
- 不存在购彩跳转。
- 不存在中奖承诺。

- 核心页面都有随机性和理性使用提示。
- 不可逾越风险门禁已逐项检查并通过。
- 真实支付、真实广告 SDK、小程序、App 上架均未在 MVP 中启用。

技术可测：

- 号码生成、权益扣减、数据导入和合规检查均有测试。
- 主要用户流程可以通过浏览器测试跑通。
- 开奖数据同步失败时系统可以稳定降级。
